# Christmas Money Club

The website for **https://christmasmoneyclub.com**. It is a static website with a browser-based holiday planner. Its production HTTP server uses only Node.js built-ins; no database or package installation is required.

## Local build and verification

Use Node.js 24:

```sh
npm run build
npm run check
npm run check:server
npm start
```

Open `http://localhost:8080`. The server listens on `0.0.0.0` and uses `PORT` when provided, otherwise port `8080`.

- `build.mjs` renders the pages from `content/`.
- `public/assets/` contains the authored CSS, JavaScript, and image.
- `dist/` is regenerated by the build. Edit the sources, then rebuild.
- `site-config.mjs` is the source of the canonical origin used by page metadata, structured data, the sitemap, robots.txt, and server redirects.
- `check.mjs` verifies planner calculations, article content, markup, and internal links.
- `check-server.mjs` starts the real server on an ephemeral port and verifies HTTP routes, assets, redirects, HEAD requests, error responses, and canonical metadata.

## Railway

The root `Dockerfile` builds and checks the site, then runs the server as the unprivileged `node` user. It includes only the generated site and server files in the runtime image. Railway can detect the Dockerfile without an additional build or start command.

Use these service settings:

- Source root: repository root.
- Port: Railway's injected `PORT`, or explicitly set `PORT=8080` and target port `8080`.
- Healthcheck path: `/healthz`.
- Custom domains: `christmasmoneyclub.com` and `www.christmasmoneyclub.com`, both attached to this service. Use the exact DNS records Railway provides.

`/healthz` returns a direct `200` response. All existing page routes serve their generated `index.html`; unknown paths return the designed page with HTTP `404`. Directory routes without a trailing slash and explicit `index.html` URLs redirect to their canonical path. The server supports `GET`, `HEAD`, correct content types, caching validators, and the security headers formerly described by `dist/_headers`.

Requests to `www.christmasmoneyclub.com` receive a `308` redirect to the same path and query at `https://christmasmoneyclub.com`. Requests for the apex with an explicit `X-Forwarded-Proto: http` also upgrade to HTTPS; forwarded HTTPS requests are served directly. Railway-generated preview domains and the healthcheck hostname remain usable without a redirect to the public domain. Page canonical metadata always uses the public domain.

This repository does not change the access settings of any separately hosted ChatGPT Site.

No `railway.json` or `railway.toml` is required: Railway's current documentation deprecates that legacy configuration format for new services. Set the healthcheck and domains on the service itself.
